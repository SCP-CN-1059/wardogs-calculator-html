# 单文件版（一个 HTML 就能用）

`炮兵计算器-单文件版.html` 把样式、脚本、地图配置、标记图标**和地图影像**全部打包进
**一个 HTML 文件**：双击就能在浏览器里打开，不需要服务器、不需要 Node、**完全不需要网络**。

界面是**精简版**：12 种语言齐全（默认跟随浏览器语言，随时可切），但去掉了地图样式选择、
无障碍面板、画图工具、导入导出、今日消息 —— 只留算炮射方位距离真正要用的东西。

## 快速开始

1. 双击 `炮兵计算器-单文件版.html`（或用浏览器“打开文件”）。
2. 打开后就是计算器：选地图、点位置/输坐标、读距离与方位。

> 它和离线版（`离线启动.cmd` + `npm run offline`）用的是**同一套代码**，区别只是
> 单文件版把数据内嵌、并按需关掉了一批功能；离线版仍然是完整界面。

## 保留了什么 / 删掉了什么

| 保留 | 说明 |
| --- | --- |
| 地图 | Bakurani / Ozeti / Zestafona 三张 + 自定义尺寸 |
| 多语言 | 12 种语言全部内嵌（英/俄/乌/德/法/西/波/葡/简中/韩/日/Cat），切换为**原地切换**，不跳转 |
| 位置选择 | 右键放炮位、左键拖目标，也可直接输坐标，含复制/粘贴、锁定 |
| 武器与射击解 | L81 迫击炮、SPH-2（距离 / 方位角 / MIL，LOW·HIGH 双解） |
| 保存目标 | 列表 + “保存”“同时保存炮位”（localStorage） |
| 相机 | 空格+左键 / 中键拖动、滚轮缩放、方向键与 WASD、全屏 |
| 侧栏宽度 | 拖动左边缘把手自定义宽度，自动记忆 |
| 工具按钮 | 只剩 4 个：测距尺、坐标搜索、图层、全屏 |

| 删掉 | 说明 |
| --- | --- |
| 地图样式按钮 | 只嵌黑白一套瓦片，选择器不再创建 |
| 无障碍面板 | 字号 / 大控件 / 高对比度那套 UI 不创建 |
| 画图功能 | 铅笔、区域、多边形、标记、橡皮、撤销/重做都不再创建；快捷键（`P`/`Z`/`G`/`E`/`M`）也一并失效 |
| 导入导出 | 地图标注的导入导出、保存目标的“全部导出/导入”都移除 |
| 今日消息 | MOTD 按钮与公告逻辑不加载 |
| 其他 | 彩色瓦片、等高线、Terrain3D 高程、联机大厅、反馈、统计、SEO 元数据 |

> 语言包很小：`locales/` 全部 12 种语言合计 **116 KB**，其中中文 + 索引本来就要 11.5 KB，
> 多语言的净增量只有 **104.5 KB（0.10 MB）**，所以保留全部语言。

单文件里没有 `/<locale>/` 路由，语言选择器因此改成**原地切换**（`switchLanguage()` 在
`isSingleFileMode()` 下直接换用内嵌词条并重绘，页面地址不变）；官方站点仍然是切换路由。

实现方式是**构建期特性开关**：构建脚本写入 `window.__WARDOGS_FEATURES__`，
应用里每处功能都只在被显式关闭时才跳过，所以**在线版 / 离线版完全不受影响**（已回归验证）。

## 操作方式

| 操作 | 效果 |
| --- | --- |
| **鼠标右键** 在地图上按下/拖动 | 设置**炮位**（拖动可连续调整，不会平移地图） |
| **鼠标左键** 在地图上拖动 | 设置**目标**（点中塔楼等预设标记时直接把它设为目标） |
| **按住空格 + 左键拖动** | 平移地图（此时左键不放置点位） |
| 鼠标中键拖动 | 平移地图 |
| 滚轮 | 以光标为中心缩放 |
| `W` `A` `S` `D` / 方向键 | 平移（`Shift` 加速） |
| **拖动左侧栏右边缘** | 自定义侧栏宽度（范围 220–560 px，自动记忆） |
| 侧栏把手上的 `←` `→` | 微调宽度（`Shift` 加大步长）；双击把手恢复默认 290 px |

因为左右键已经是固定的「炮位 / 目标」，左侧栏的 **炮位 / 目标** 按钮改为“坐标输入框正在编辑
哪个点”；用鼠标放点时会自动跟着切过去。

**右键拖动不会再弹出浏览器菜单**：地图区域内的右键菜单一律屏蔽；拖动过程中以及拖动结束后
600 ms 内整个页面屏蔽（右键拖动常在侧栏或工具栏上松手，而菜单是按“松手时指针下的元素”弹出的）；
同时用 pointer capture 让整段拖动都归地图接收（移出画布、甚至移出窗口也不会卡住），
并用 `user-select: none` 避免拖出文本选中。

按住空格时鼠标变成“抓手”，松开即恢复。

### 影像精度策略

按“只有中间塔楼附近才是真正交战区”的前提分配体积：

| 区域 | 层级 | 说明 |
| --- | --- | --- |
| 全图 | z0–z4 | 保证任意缩放/平移到任何位置都有底图（Fit 视图用的是 z2） |
| 塔楼 ±1.5 km（3×3 km） | z5–z7 | 全精度，z7 约 2 px/m，够精确点选坐标 |
| 其他区域放大时 | 自动回退到 z4 底图放大 | 会变糊但不会出现黑块 |

塔楼中心（由地图里的 Tower 标记自动算出）：Bakurani (80.2, 70.9)、Ozeti (100.3, 63.3)、
Zestafona (70.6, 103.1)，单位是 100 m。

**不含**：彩色瓦片（只保留黑白）、等高线图层、Terrain3D 高程
（单文件里高程数据太大；SPH-2 会照常给出平表解，地形修正不可用）、联机大厅、反馈、统计。

## 体积与重新生成

当前产物（实测）：

| 项目 | 数值 |
| --- | --- |
| 内嵌瓦片 | 3527 张（Bakurani 1184、Ozeti 1184、Zestafona 1159） |
| 原始 WebP 数据 | 112.02 MB |
| 重新编码为 JPEG q65（灰度） | 22.59 MB |
| 内嵌语言 | 12（全部） |
| 裁剪掉的界面元素 | 10 处 |
| **最终 HTML** | **31.02 MB** |

体积几乎全部是影像；关掉那批界面功能只省几十 KB，真正的“瘦身”要靠下面的影像参数。

想要更小/更清晰，都能用参数重生成（编码用 Pillow，本机已装 Python 3.12 + Pillow 12.3）：

```bash
npm run build:single                                   # 默认：三图 + 塔楼±1.5km + 全图 z4 + JPEG q65
npm run build:single -- --base-max-zoom 3               # 全图只到 z3，省约 7 MB（外围更糊）
npm run build:single -- --detail-radius-km 1            # 精区缩到 2×2 km，省约 10 MB
npm run build:single -- --quality 55                    # 再压一点，省 2–3 MB
npm run build:single -- --maps bakurani                 # 只要一张图，约 11 MB
npm run build:single -- --format webp                   # 改用 WebP（同画质约小 25–30%）
npm run build:single -- --no-reencode                   # 不重编码，直接内嵌原 WebP（最大、最清晰）
npm run build:single -- --out 小地图.html               # 自定义输出名
```

界面范围的参数（两个成品用的就是这一组：保留多语言，其余精简）：

```bash
npm run build:single -- --features locales --all-languages   # 当前两个成品的界面配置
npm run build:single -- --full                               # 恢复完整界面（含地图样式/无障碍/画图/导入导出/MOTD）
npm run build:single -- --features locales,mapStyle          # 只保留指定功能
npm run build:single -- --languages zh-cn,en                 # 只嵌部分语言
```

可选功能名：`locales`（语言切换）、`mapStyle`（地图样式按钮）、`accessibility`（无障碍面板）、
`drawingTools`（画图工具）、`dataTransfer`（导入导出）、`motd`（今日消息）。

估算时记住：**体积 ≈ 塔楼精区面积**（z7 占大头，半径减半即省约 3/4），
全图底图 z0–z4 每张图约 2.7 MB（原图）。

构建脚本：`scripts/build-single-file.mjs`（装配 HTML + 特性开关 + 裁剪标记）+
`scripts/lib/single-file-tiles.py`（Pillow 把瓦片转成 JPEG data URI，灰度单通道）。

## 轻量版（约 5 MB）

`炮兵计算器-单文件版-5MB.html`：同样的中文精简界面，只把**影像预算**换了一种分法 ——
**非交战区只留 zoom_2，交战区留到 JPG 压缩的 zoom_6**：

| 区域 | 层级 | 说明 |
| --- | --- | --- |
| 全图 | z0–z2 | 三张图各 21 张瓦片（Fit 视图正好用的是 z2，所以打开就是清晰可认的全图） |
| 塔楼 ±1 km（2×2 km） | z3–z6 | JPEG（灰度）压缩，z6 约 1 px/m，够精确点选坐标 |
| 交战区以外放大时 | 自动回退 z2 底图放大 | 很糊（2×2 km 以外只有 z2 精度），但不会黑屏 |

生成命令与实测：

```bash
npm run build:single -- --out 炮兵计算器-单文件版-5MB.html \
    --features locales --all-languages \
    --base-max-zoom 2 --detail-min-zoom 3 --max-zoom 6 --detail-radius-km 1
```

| 项目 | 数值 |
| --- | --- |
| 内嵌瓦片 | 420 张（每图 21 张底图 + 约 119 张交战区） |
| 原始 WebP 数据 | 14.43 MB |
| 重新编码为 JPEG q65（灰度） | 2.99 MB |
| 内嵌语言 | 12（全部，与主版一致） |
| **最终 HTML** | **4.73 MB** |

尺寸换算参考（三张图、JPEG q65、全图 z0–z2）：

| 交战区半径 | 内嵌瓦片 | HTML |
| --- | --- | --- |
| ±1.0 km（本版） | 420 | **4.6 MB** |
| ±1.25 km | 598 | 6.6 MB（估算） |
| ±1.5 km（本项目另一版的做法） | 781 | 8.2 MB（估算） |

`--max-zoom 6` 还有一个附带效果：内嵌的地图配置会把 `tiles.maxZoom` 写成 6，
渲染器因此**直接请求 z6** 而不是先请求不存在的 z7 再回退，省掉无谓的瓦片查找。

### 轻量版验证（实测）

- 内嵌 `baseZoom={bakurani:2,ozeti:2,zestafona:2}`、内嵌地图配置 `maxZoom=6`、瓦片键 420 个；
- Fit 视图加载的层级为 `{"0":1,"2":16}` —— 正好是全图底图；
- 放大到塔楼区（相机倍率 40）加载 `{"0":1,"2":16,"6":28}` —— 交战区命中 z6；
- 平移出交战区同倍率下仍是 `{"0":1,"2":16,"6":28}`（底图全部命中的缓存，回退不产生额外请求），
  画面为 z2 放大（`darkPixelRatio=0.00`，不黑屏）；
- 射击解正常：SPH-2 `dist=1.22 km / azimuth=55.0° / mil=28 / 1286`（`射程内`）；
- `nonFileResourceEntries=0` —— 依然一个外部请求都没有。

## 回归验证（在线版 / 离线版不受影响）

同一套代码在本地服务下打开时：语言选择器（12 种语言）、地图样式（黑白/彩色）、
8 个工具按钮、保存目标导出/导入、MOTD 铃铛、无障碍「Aa」启动器全部照常存在；
`npm run test:scripts` 19 项、`npm run build`、`npm run test:build` 全部通过。

## 已知限制

- **文件较大（约 31 MB）**，首次打开需要几秒解析；打开后所有操作都在本地，无延迟。
- 手机浏览器也能打开，但用的是桌面界面（单文件版没有 `/mobile/` 路由）。
- 地图影像为灰度 JPEG，比在线版略糊（在线版是 WebP 原图）；塔楼区最清晰。
- 语言切换是原地的（单文件没有 `/<locale>/` 路由），所以地址栏不会变成 `/ru/`；
  官方站点仍是切换路由以保留 SEO。
- 不含地形高程与等高线，SPH-2 显示平表解。
- 没有导入导出，`localStorage` 在 `file://` 下按浏览器实现保存：换浏览器或清缓存会丢保存目标，
  需要备份时请用完整版（离线版）的导出功能。
